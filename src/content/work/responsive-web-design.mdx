## The Problem

The existing product had been built in pieces — a desktop web app, a mobile wrapper, and a separate marketing site — each with different interaction patterns and visual languages. Users were context-switching constantly, and the support queue was full of "where did X go?" tickets.

The ask: consolidate it into one coherent responsive experience without losing any existing functionality.

## Approach

Started with a full audit. Cataloged every distinct interaction pattern across the three surfaces, then mapped which ones were actually redundant vs. genuinely necessary. Ran a three-day contextual inquiry with eight users across device types to see where the pain was real vs. assumed.

Key finding: mobile users weren't trying to do less — they just couldn't. The desktop layout was being viewport-crushed, not adapted.

## The Work

Designed a component-first layout system built around a fluid 12-column grid with four breakpoints. Every component was designed at three states before any screen was composed — this forced real decisions about information priority instead of letting them get deferred to "we'll fix it on mobile."

Collaborated closely with engineering on the technical constraints early. A few interaction patterns I initially spec'd were infeasible given the existing backend — we worked through alternatives together rather than handing over a finished spec that couldn't ship.

Ran two rounds of usability testing mid-build, which surfaced a navigation model problem I hadn't caught in wireframes. Revised the information architecture before the final build.

## Results

Shipped on schedule. Mobile session depth increased 41% in the first month. Support tickets about navigation dropped significantly. The component system also became the foundation for the next two product features — the team stopped rebuilding from scratch each time.
